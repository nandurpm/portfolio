# Android 2.10.6 — Source-level audit and targeted simplification

## Scope and evidence

Reference: tracker-v2.10.5 (published 2026-11-09). Baseline code was read from `main`. No production financial data, account credentials, production SQL, signing keys or Supabase configuration were accessed or changed.

## Confirmed source findings

| Priority | Finding | Fix in this branch |
| --- | --- | --- |
| High | Accounts transaction save has no in-flight guard, permitting consecutive submit attempts while a duplicate confirmation is pending. | Add synchronous ref lock and a disabled Save state with finally cleanup; add synthetic regression. |
| Medium | Android Home repeats monthly figures in balance insights, KPIs and pulse, delaying actual money activity. | Keep one 3-KPI summary and one budget bar above recent activity; retain advanced figures inside a disclosure. |
| Medium | Direct transfer entry requires several taps through Accounts, and native Home has no direct transfer action. | Open the existing blank Accounts form with transfer type and scroll it into view; no auto-save. |
| Medium | Recent neutral ledger movements display the literal label "Transfer" as the amount, even for other principal movements. | Display the existing recorded movement amount with neutral styling; calculations unchanged. |
| Medium | Secondary entries, budget and opening-balance tools occupy the initial phone viewport. | Keep forms and monthly budget visible; collapse optional totals, settings and bulk tools. |
| Low | More contains duplicate Forecast and balances destinations, and uses static purple colors even under non-Lavender palettes. | Consolidate to nine distinct shortcuts in three groups; use shared palette tokens. |

## Financial and platform invariants

No accounting engine, interest/EMI formula, ledger posting rule, data model, schema migration or synchronization protocol was changed. Display-only changes must not be interpreted as altered financial totals. The Android manifest, application ID and signing identity were not modified.

## Tests and limitations

The new Playwright tests use the disposable browser harness and synthetic accounts, never a production user. GitHub CI must validate quality, finances, a disposable DB/Supabase stack and Android compile before merge. Android emulator signing/upgrade testing remains a release workflow gate. Actual physical device widget appearance, theme-to-widget palette parity, app-lock interaction, Supabase production account sync, real-world Telegram delivery, Windows Authenticode and OEM launcher behaviour are **NOT VERIFIED** by source inspection or browser simulation alone.

The separate widget designs introduced in v2.10.5 remain unchanged in this release. Their light/dark native resources follow Android system appearance, not necessarily the app's selected palette. Theme parity across the widget bridge is a remaining enhancement, not a verified fix.
